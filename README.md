# 黑白视频转深度视频（浏览器本地运行）

把黑白或普通视频逐帧转换成"伪深度"视频的纯前端网页应用。所有 AI 推理与视频编码都在你的浏览器本地完成，无需服务器、无需上传视频、无需 API Key。

> 仓库名：Monochrome-to-Depth-Video-Conversion-test

## 一、这个项目解决什么问题

- 将一段普通（或黑白）视频逐帧重绘为表达"每个像素离镜头多远"的单色深浅视频，可用于动作提取、3D 观感、视频特效等场景。
- 完全在本地浏览器运行：**视频不经过任何服务器**，从根源上保护隐私；不依赖云端算力，离线也能用。
- 零部署门槛：既能通过 GitHub Pages 在线打开分享，也能下载到本地用本地服务器加速运行。

## 二、主要功能

- **本地 AI 深度估计**：基于 Depth Anything V2 Small 模型，在浏览器内用 Transformers.js 完成推理。
- **视频零上传**：文件仅在本地内存处理，不会发送到任何服务器。
- **参数可调**：
  - 输出宽度 / 高度，支持锁定宽高比；
  - 采样帧率（fps）；
  - 开始时间 / 结束时间（截取片段）；
  - 深浅方向（近处亮 或 远处亮）；
  - 叠加原图轮廓（让主体更清晰）。
- **实时预览**：原帧与深度帧左右同步显示。
- **导出 MP4**：用 ffmpeg.wasm 把逐帧结果封装为视频文件，可直接保存到本地文件夹或下载。
- **设备自适应**：电脑端优先使用 WebGPU / 多线程加速；移动端自动降配以防卡死。
- **两种运行方式**：在线（GitHub Pages）分享，或本地服务器（更快、多线程）。

## 三、安装方法

本项目是纯静态网页，无需编译。

**方式一：在线使用（最简单，适合分享）**

- 直接用浏览器打开 GitHub Pages 链接即可（见"使用方法"）。
- 首次打开会从网络下载深度模型（约 100MB），加载后浏览器会缓存，之后更快。

**方式二：下载到本地运行（推荐，更快）**

1. 在仓库页面点 `Code → Download ZIP`，解压到本地任意目录。
2. 安装 Node.js（LTS 版，官网下载，安装时勾选"Add to PATH"）。无需安装其他依赖。
3. 进入解压后的目录，双击 `start.bat`（Windows）启动本地服务器。

> 若没有 Node.js，也可改用 Python 替代：
> `python -m http.server 8777`，再打开 http://localhost:8777
> 注意：此方式没有跨源隔离头，WASM 为单线程，速度稍慢，但仍可用。

## 四、使用方法

**在线使用**

- 打开 GitHub Pages 链接：
  `https://poemtrind.github.io/Monochrome-to-Depth-Video-Conversion-test/`
- 首次打开需下载模型（约 100MB），请耐心等待加载完成。

**本地运行**

1. 双击 `start.bat` 启动本地服务器（脚本不会自动打开浏览器，请手动在浏览器地址栏输入 `http://localhost:8777`）。
2. 浏览器打开 `http://localhost:8777` 即可。

**转换步骤（在线 / 本地相同）**

1. 点「加载深度模型」（首次约需几秒到十几秒，取决于机器与网络）。
2. 选择要转换的视频文件。
3. 按需设置：输出宽度 / 高度（可锁定宽高比）、采样帧率、开始 / 结束时间、深浅方向、是否叠加原图轮廓。
4. 点「开始转换」，处理完成后保存或下载生成的深度视频。

**停止本地服务器**：关闭 `start.bat` 弹出的黑色窗口即可。

## 五、残留问题 / 待优化

- **移动端（手机）转换仍不稳定**：部分机型转换结果异常（如黑帧、画面不对），且整体速度明显慢于电脑端。
- 原因是移动端算力有限、推理以单线程为主，代码已做降配（限制分辨率与帧率）来尽量避免卡死，但体验仍有差距。
- **欢迎有兴趣的同学帮忙修改、优化移动端逻辑，或提交改进建议！**

## 附：工作原理（简述）

- 纯前端架构：HTML + CSS + 原生 JavaScript（ES Module），通过 importmap 引用本地打包的库，完全离线。
- 深度估计：Transformers.js + ONNX Runtime Web，模型为 Depth Anything V2 Small（本地 onnx 权重）。
- 视频编码：ffmpeg.wasm（libx264）在浏览器内封装 MP4。
- 本地更快的原因：本地服务器会设置跨源隔离响应头（COOP / COEP），从而启用 WASM 多线程；静态托管（GitHub Pages）无法设置这些头，因此在线版为单线程。
